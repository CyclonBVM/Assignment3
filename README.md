## 一、功能说明

- **流水灯**：3 颗 LED（PA0/PA1/PA2，共阳接法、低电平点亮），同一时刻只亮 1 颗，切换间隔 100~2000ms 可调；
**
- **按键**：KEY1（PA11）切换正向/反向，KEY2（PA12）切换暂停/继续；两个按键都经 20ms 消抖；暂停期间按键仍然有效；
- **串口控制**：电脑通过 USB 转 TTL 发送 6 字节 HEX 数据包，可一次性设置运行/暂停、方向、切换间隔；帧头或校验和不对时不执行；。
- **OLED 显示**：软件 I²C（PB1=SCL、PB0=SDA）驱动 SSD1315，4 行显示状态、方向、间隔、当前 LED 编号，按键与串口操作同步刷新；
- **串口反馈**：数据包应用成功、按键改变运行状态或方向后，通过串口中断回传一行状态。

## 二、接线表

| 功能 | 引脚 | 说明 |
|---|---|---|
| LED0 / LED1 / LED2 | PA0 / PA1 / PA2 | 共阳接法：3V3 — 1kΩ — LED — 引脚，低电平点亮 |
| KEY1（方向） | PA11 | 按键另一端接 GND，内部上拉，下降沿触发 |
| KEY2（暂停） | PA12 | 同上 |
| USART1 | PA9 = TX、PA10 = RX | 接 USB 转 TTL（3.3V 电平），TX/RX 交叉，必须共地 |
| OLED | PB1 = SCL、PB0 = SDA | 3.3V 供电、共地 |
| 调试 | PA13 / PA14 | ST-Link SWD（勿占用） |

## 三、串口数据包协议

每包固定 6 字节，十六进制：

```
AA  RUN  DIR  STEP_L  STEP_H  CHECK
```

| 字段 | 字节数 | 约定 |
|---|---|---|
| 帧头 | 1 | 固定 `0xAA` |
| RUN | 1 | `00` 暂停，`01` 运行 |
| DIR | 1 | `00` 正向，`01` 反向 |
| STEP | 2 | 间隔毫秒数，范围 100~2000，**低字节在前**、高字节在后 |
| CHECK | 1 | `(0xAA + RUN + DIR + STEP_L + STEP_H) % 256`（含帧头，保留低 8 位） |

示例（串口助手选 HEX 发送，不加换行）：

| 期望设置 | 6 字节 |
|---|---|
| 运行、正向、300ms | `AA 01 00 2C 01 D8` |
| 暂停、正向、300ms | `AA 00 00 2C 01 D7` |
| 运行、反向、300ms | `AA 01 01 2C 01 D9` |
| 暂停、反向、1000ms | `AA 00 01 E8 03 96` |
| 运行、反向、100ms | `AA 01 01 64 00 10` |
| 暂停、正向、2000ms | `AA 00 00 D0 07 81` |

接收侧用文本模式（GBK）查看英文反馈。

## 四、自定义串口反馈格式

格式（一行，`\r\n` 结尾）：

```
STATE=RUN,DIR=FWD,STEP=300,LED=1
```

| 字段 | 含义 |
|---|---|
| STATE | `RUN` 运行 / `PAUSE` 暂停 |
| DIR | `FWD` 正向 / `BWD` 反向 |
| STEP | 相邻 LED 切换间隔（毫秒） |
| LED | 当前点亮的 LED 编号（1~3） |

触发时机：数据包校验通过并应用后；按键改变运行状态或方向后；上电初始化后各发送一帧。不逐次切灯发送。

## 五、关键实现说明

1. **唯一状态源**：`SysState` 保存运行标志、方向、间隔、当前 LED、时间戳；按键与串口只修改它，LED/OLED/串口反馈都从它读取，因此三处显示永远一致。
2. **中断只做记录**：EXTI 回调只记录时间戳与标志；串口接收回调按字节喂给组包状态机（帧头同步），收满一包后拷副本、置标志并立即重新启动接收；校验/解析/状态更新/显示/反馈都在主循环完成。
3. **非阻塞调度**：不使用 `HAL_Delay` 控制灯，而是比较 `HAL_GetTick()` 时间戳，因此访问间隔为 2000ms 时按键与串口也能立即响应（对应思考题）。
4. **数据包必须 `packed`**：否则结构体因对齐变成 8 字节，第 6 字节校验位落不进去；代码中加入 `_Static_assert(sizeof(Packet) == 6)` 防止回归。
5. **收包可自动重同步**：逐字节接收 + 帧头 `0xAA` 同步，多发的换行、上电半包、丢字节都能在下一个帧头恢复，不会永久错位；主循环取副本时用临界区保护。
6. **软件 I²C OLED**：PB1=SCL（推挽）、PB0=SDA（开漏，高电平靠模块自带上拉），页寻址模式写入，8×16 字模；带脏标记与行缓存，只重画内容变化的行。**驱动芯片为 SSD1315**（命令与 SSD1306 基本兼容，额外用 `0xAD 0x30` 设置内部 IREF；上电延时 100ms；可用 `OLED_CONTROLLER_SSD1315` 宏切回纯 SSD1306）。若屏幕不亮：先查接线/共地/上拉，再把 `oled.c` 里 `OLED_I2C_ADDR` 从 `0x78` 改为 `0x7A` 试。

## 七、思考题

> 切换间隔较长（如 2000ms）时，按键和串口指令不能立刻执行、有延迟，问题出在哪里，如何改进？

问题出在**阻塞式延时**：若用 `HAL_Delay(2000)` 控制流水灯，CPU 在延时里无操作，主循环不检查按键标志，不处理串口数据，按键中断虽能置标志但不处理，表现为"响应延迟"。

改进：主循环不断比较 `HAL_GetTick()` 与上次切换时刻，到点才切换，其余时间处理按键、串口、显示；也可用定时器更新中断产生节拍标志。同时避免在主循环做长耗时操作。此工程两者都做了（时间戳调度 + 脏标记/行缓存刷新）。
